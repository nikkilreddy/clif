THE 5 MANDATORY PITCH QUESTIONS (SCORED DIRECTLY BY JUDGES)
================================================================================

--------------------------------------------------------------------------------
Q1: WHAT PROBLEM, AND WHO EXACTLY HAS IT?
--------------------------------------------------------------------------------
ANSWER:
"Tier-1 and Tier-2 SOC (Security Operations Center) Analysts and Incident Responders.

They face an alert fatigue crisis: over 10,000 alerts per 8-hour shift with a 45%+ false-positive rate. When an actual breach occurs, manually correlating fragmented logs across dozens of servers, firewalls, and databases takes hours to days. Real attackers dwell inside networks for months because analysts are drowning in benign noise."

--------------------------------------------------------------------------------
Q2: WHAT IS THE NON-OBVIOUS HARD PART?
--------------------------------------------------------------------------------
ANSWER:
"Two interconnected challenges:

1. Preventing ML Data Leakage across 60 features:
Engineering a 60-feature extractor across 10 diverse log types without tautological target contamination. It survived 7 rounds of rigorous leakage auditing to eliminate severity leaks, tautological SSH failure counts, and temporal train-test overlap.

2. Zero-Loss Ingestion Orchestration at Line Rate:
Building a high-throughput streaming architecture (Rust Vector -> Redpanda -> Go Consumer -> ClickHouse) utilizing zero-allocation buffer swaps, LZ4 compression, and deterministic UUID5 deduplication to process over 35,000 events/second with sub-100ms query latency."

--------------------------------------------------------------------------------
Q3: WHAT DID YOU BUILD THAT THE API DIDN'T GIVE YOU? (THE KNOCKOUT QUESTION)
--------------------------------------------------------------------------------
ANSWER:
"We built the entire platform from scratch with ZERO generic prompt wrappers. 
No API exists that can do this because throwing 10,000 logs/sec to OpenAI or Claude causes rate limits, costs thousands in API bills, and hallucinates fake CVEs.

Specifically, we built:
1. Custom Rust Vector transforms (VRL) for real-time log normalization.
2. A high-performance Go streaming consumer with worker pools and LZ4 compression (35,000+ EPS).
3. A 60-feature extractor across 7 domain layers.
4. Trained dual-model ONNX ensemble: Supervised LightGBM + Unsupervised Neural Autoencoder running locally in 10 microseconds per event.
5. A 5-engine Hunter investigation layer (Sigma rules, 3-sigma statistical anomalies, temporal causality, and topological Attack Graph builder).
6. A calibrated Verifier forensic decision engine with an explicit 'Inconclusive' fallback.
7. A modern Next.js SOC analyst investigation dashboard."

--------------------------------------------------------------------------------
Q4: WHY DOES THIS BREAK IF YOU REMOVE THE AI?
--------------------------------------------------------------------------------
ANSWER:
"Without the AI pipeline, the system collapses into a passive, dumb log bucket:
1. Line-rate logs cannot be prioritized, scored, or filtered.
2. Cross-host lateral movement and 3-sigma behavioral anomalies cannot be detected by static IF-ELSE rules.
3. Multi-node Attack Graphs linking external IPs, compromised users, and database tables cannot be constructed.
4. Security cases cannot be autonomously investigated or explained to human analysts in plain English."

--------------------------------------------------------------------------------
Q5: WHAT BREAKS AT TEN THOUSAND USERS (OR 1,000,000 EPS)?
--------------------------------------------------------------------------------
ANSWER:
"1. ClickHouse Memory Pressure:
High-concurrency graph traversal queries over unpartitioned historical data would exhaust RAM. In enterprise production, we mitigate this through date-based partition sharding, tiered data retention policies (hot/warm storage), and horizontal ClickHouse replica clusters.

2. Kafka Partition Rebalancing Lag:
During sudden 1M EPS bursts, consumer groups can experience rebalance latency. We mitigate this by pre-partitioning topics into 32+ partitions and dynamically scaling our Go worker pools."

ADDITIONAL TOUGH JUDGE QUESTIONS & BULLETPROOF ANSWERS
================================================================================

--------------------------------------------------------------------------------
Q6: HOW DO YOU HANDLE BEING WRONG & GRACEFUL DEGRADATION?
--------------------------------------------------------------------------------
ANSWER:
"We use a strict 3-tier verdict matrix: True Positive, False Positive, and Inconclusive.
If investigation inputs are contradictory, logs are missing, or a tool times out, the Verifier Agent NEVER guesses or triggers an unsafe automated action. It reduces confidence and safely defaults to an explicit 'Inconclusive' verdict with wide confidence bounds."

--------------------------------------------------------------------------------
Q7: WHY USE TWO MODELS INSTEAD OF ONE?
--------------------------------------------------------------------------------
ANSWER:
"We use a cooperative two-model ensemble:
- Model 1 (LightGBM): Fast supervised tree classifier trained to spot known attack signatures.
- Model 2 (Neural Autoencoder): Unsupervised deep neural network trained to detect abnormal reconstruction error on zero-day anomalies.

If an attacker obfuscates their payload so LightGBM misses it (score 0.000), the Autoencoder catches the high reconstruction error (score 0.920) and escalates it to the Hunter Agent anyway."

--------------------------------------------------------------------------------
Q8: HOW IS THIS DIFFERENT FROM MICROSOFT SENTINEL OR SPLUNK SOAR?
--------------------------------------------------------------------------------
ANSWER:
"1. Microsoft Sentinel Copilot: Relies on single-prompt LLM chat queries over cloud logs, whereas CLIF runs an autonomous 3-agent pipeline with local microsecond ONNX scoring.
2. Splunk SOAR: Uses rigid, hand-coded IF-ELSE playbooks that break under unknown attack variants, whereas CLIF uses an autonomous investigation loop with temporal graph reasoning."
